## Context

Loom milestone M9 / v0.3.0 scope has landed all four implementation slices per ADR 0034 §5:
- Slice 1 (`hc-host-adapter`): `loom-host-hc` observation/cleanup helper, binding `hc-host/v1`, v0.3.0 matrix floor `0.1.16`.
- Slice 2 (`hc-live-probe`): generic live probe script `scripts/hc-live-probe` and offline suite, live probe run against `hc 0.1.16`.
- Slice 3 (`orca-host-adapter`): `loom-host-orca` observation/cleanup helper, binding `orca-host/v1`, v0.3.0 matrix floor `1.4.250`.
- Slice 4 (`antigravity-model-adapter`): Antigravity model adapter, model provider family resolution, cross-family invariant enforcement, author routing persistence, and v0.3.0 matrix floor `1.4.12`.

Per ADR 0034 §4 and §5, the final milestone delivery is **Slice 5: `v0.3.0-live-proof`**.
This slice executes the formal v0.3.0 release transition:
1. Amends `loom-release-evidence-v1.schema.json` to admit v0.3.0 alongside v0.2.0, supporting the five admitted v0.3.0 pairs (`claude-code-cli`, `codex-cli`, `antigravity-cli`, `orca-host`, `hc-host`) with host harness evaluator delegation rules per ADR 0034 §2.
2. Updates `scripts/validate-repository.mjs` to support v0.3.0 release evidence validation, multi-release evidence chains, and the `--release` verification mode.
3. Bumps product release version to `0.3.0` across manifests (`.claude-plugin/plugin.json`, `.codex-plugin/plugin.json`), toolchain contracts (`scripts/check-toolchain.json`, `scripts/check`), launcher constant (`DEFAULT_COMPATIBILITY_RELEASE="0.3.0"` in `plugins/loom/bin/loom-launch-role`), and `CHANGELOG.md` (`## [0.3.0]`).
4. Creates v0.3.0 release fixtures for manifests and catalog, while maintaining the mechanical byte-identity invariant for the six v0.2.0 baseline files.
5. Verifies candidate commit against full repository gate (`scripts/check`) under both macOS Bash 3.2.57 and Bash 5.3+, tagging candidate `v0.3.0`.
6. Executes live conformance runs (E4) across all five pairs at their pinned floors, records the sanitized evidence archive, and commits `.docs/evaluations/release-evidence/v0.3.0.json` (E4–E5) on `main`.

## Out of Scope & Threat-Model Boundary

- **No retrospective mutation of v0.2.0:** The tagged `v0.2.0` release and `.docs/evaluations/release-evidence/v0.2.0.json` remain immutable. The six v0.2.0 baseline files remain byte-identical to `git show v0.2.0:<path>`.
- **No live hc or Orca evaluators:** ADR 0031 §5 and ADR 0034 §2 strictly prohibit `hc` and Orca evaluator sessions. In E4, host harnesses run interactive roles only; evaluators run in isolated POSIX workspaces with certified model CLIs (`codex` or `claude`).
- **Archive sanitization:** Logs and journals are external to the repository; the evidence archive `loom-release-evidence-v0.3.0-<candidate>.tar.gz` contains sanitized logs only (no secrets, no environment dumps, absolute paths scrubbed).

## Steps

1. **Schema Amendment (`plugins/loom/schemas/loom-release-evidence-v1.schema.json`)**:
   - Update top-level `release`: `{ "enum": ["0.2.0", "0.3.0"] }`.
   - Update `tag`: `{ "enum": ["v0.2.0", "v0.3.0"] }`.
   - Update `matrix`: `{ "enum": ["plugins/loom/adapters/compatibility/v0.2.0.json", "plugins/loom/adapters/compatibility/v0.3.0.json"] }`.
   - Update `pairs`:
     - If `release == "0.2.0"`: requires exactly 2 pairs (`claude-code-cli`, `codex-cli`).
     - If `release == "0.3.0"`: requires exactly 5 pairs (`claude-code-cli`, `codex-cli`, `antigravity-cli`, `orca-host`, `hc-host`).
   - Add pair definitions and floor bindings for `antigravity-cli` (floor `1.4.12`, root `antigravity-plugin-root/v1`), `orca-host` (floor `1.4.250`, binding `orca-host/v1`, host `orca`), and `hc-host` (floor `0.1.16`, binding `hc-host/v1`, host `hc`).
   - For host harnesses (`orca-host`, `hc-host`), support E4 evaluator delegation metadata specifying delegated evaluator harness (`codex-cli` or `claude-code-cli`) and isolated workspace verification per ADR 0034 §2.
   - Update `ownerAck.pairs`: admit the 5 harness IDs.

2. **Repository Validator (`scripts/validate-repository.mjs`)**:
   - Update `validateReleaseEvidenceChain` to discover and validate both `v0.2.0.json` and `v0.3.0.json` chains.
   - Add `--release <version>` CLI option to validate-repository for release-time verification per ADR 0034 §4.
   - Support `v0.3.0` metadata validation: match pair entries against `clientFloors` or `hostFloors` in `v0.3.0.json`.
   - Validate that `CHANGELOG.md` contains valid `## [0.3.0]` release section with non-blank entries.
   - Preserve `validateAntigravityRoot` and mechanical byte identity check for the six v0.2.0 baseline files.

3. **Product Release Version Bump to 0.3.0**:
   - In `plugins/loom/.claude-plugin/plugin.json`: `"version": "0.3.0"`.
   - In `plugins/loom/.codex-plugin/plugin.json`: `"version": "0.3.0"`.
   - In `plugins/loom/bin/loom-launch-role`: `DEFAULT_COMPATIBILITY_RELEASE="0.3.0"`.
   - In `scripts/check-toolchain.json`: `"productVersion": "0.3.0"`.
   - In `scripts/check`: update jq toolchain contract literal to `productVersion: "0.3.0"`.
   - Re-pin `check-toolchain.json` digest for modified schema.
   - In `CHANGELOG.md`: add `## [0.3.0]` section documenting M9 deliverable features (Herdr host adapter, Orca host adapter, Antigravity model adapter, cross-family evaluation, host evaluator governance).

4. **v0.3.0 Metadata Fixtures**:
   - Add `plugins/loom/adapters/fixtures/v0.3.0/metadata/claude-manifest.json` (version 0.3.0).
   - Add `plugins/loom/adapters/fixtures/v0.3.0/metadata/codex-manifest.json` (version 0.3.0).
   - Add `plugins/loom/adapters/fixtures/v0.3.0/metadata/compatibility.json` matching `v0.3.0.json`.
   - Wire fixtures into `scripts/validate-repository.mjs` for v0.3.0 metadata validation.

5. **Test Suite Updates**:
   - In `plugins/loom/bin/loom-launch-role.bats`: update default release tests to expect `0.3.0`, and assert `--release 0.2.0` and `--release 0.3.0` dispatch appropriately.
   - In `scripts/tests/repository-validation.bats`: add test coverage for v0.3.0 release evidence schema validation, 5-pair requirement, host harness evaluator delegation, below-floor refusal, and `--release 0.3.0` flag.

6. **Candidate Commit, Tagging & E4–E5 Release Evidence Record**:
   - Commit Steps 1–5 to `main` as candidate commit. Run full gate `scripts/check` under Bash 3.2.57 and Bash 5.3+.
   - Tag candidate commit `v0.3.0`.
   - Assemble recorded live proof runs for all five harnesses into sanitized evidence archive `loom-release-evidence-v0.3.0-<candidate>.tar.gz` with `MANIFEST.sha256`.
   - Author `.docs/evaluations/release-evidence/v0.3.0.json` with candidate hash, pair runs, gate logs, and owner acknowledgment (E5).
   - Verify `scripts/validate-repository.mjs --release 0.3.0` and `node scripts/validate-repository.mjs --all`.
   - Commit evidence record to `main`.
